# PEQ v0.1 Hardening Passes — 2026-08-14

## Pass 1 — Integrity / Input Hardening

Fixed and verified:

- Malformed runtime multimodal measurements now fail closed instead of raising from `float()` conversion.
- Non-finite evidence contribution values (`NaN`, `+/-inf`) are treated as inert evidence rather than propagating invalid arithmetic.
- Retrieval request size and range are bounded:
  - query <= 4096 characters
  - top_k 1..50
  - alternatives_k 0..20
  - min_score 0..1
- Retrieval token fan-out is bounded to 64 query tokens.
- Non-finite/invalid response stakes fall back to a safe mid-range value.
- Retrieval alternatives preserve the existing API semantics while explicitly marking reused ranked interpretations as `distinct_from_leader=False`.

## Pass 2 — Concurrency / Determinism / Public-API Stress

- 160 concurrent `PEQSystem.assess()` + retrieval calls across 16 threads: 0 exceptions.
- Repeated identical semantic inputs: deterministic state/response results (UUID run IDs excluded).
- Retrieval boundary requests at minimum/maximum allowed limits: pass.
- Full pytest suite: 48 passed.
- Python compilation: pass.
- Generated bytecode/cache removed from working tree before packaging.

## Remaining intentional limitations

- PEQ probabilities are model-derived operational posteriors, not empirically calibrated probabilities.
- The scientific retrieval registry is curated source metadata, not a participant-level scientific database.
- Scientific retrieval remains a navigation/evidence-selection layer; retrieved sources do not silently become factual evidence about the current person.
- The response vocabulary remains bounded and deterministic pending a richer evidence-backed response appraisal model.
